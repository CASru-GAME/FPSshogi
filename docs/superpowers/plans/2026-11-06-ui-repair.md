# FPSshogi UI Repair Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Resolve the 12 reviewed UI problems in the runnable Unity project.
**Architecture:** Add runtime uGUI composition, board/HUD views and a session menu controller. Expose board selection and player cooldowns without duplicating game rules. Preserve all restored assets.
**Tech Stack:** Unity 6000.2.12f1, uGUI 2.0, Input System 1.14.2, C#.
**Spec:** `docs/superpowers/specs/2026-11-06-ui-repair-design.md`

## Global Constraints
- Work in the restored project on `fix/ui-usability`; retain restoration changes.
- Local two-player gameplay; Japanese copy and portable Japanese font.
- Verify 1280x720 and 1920x1080.
- Pause preserves match state and objects; countdown uses unscaled time.
- No automatic five-second exit from match results.

## Review Focus
- Disconnecting a controller during a duel must preserve HP/objects and wait for reconnection.
- Submitting a menu must not also move/attack/select a board piece in that frame.
- Repeated matches must not leave UI roots, callbacks, timescale or cursor state behind.
- Empty/last captured pieces and invalid drops must not leave false selection/quantity.
- Modal windows and split HUD must remain inside the screen at both resolutions.
