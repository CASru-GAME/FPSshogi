# FPSshogi left menu UI implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. User approved implementation of the reviewed left menu design.

**Goal:** Implement the approved room-and-pieces UI throughout the existing Unity game.
**Architecture:** Retain runtime uGUI and existing device/game rules. Use real prefab models for title staging and cached piece portraits. Split menu pages, visual primitives, transitions, and session navigation so UI does not own combat rules.
**Tech Stack:** Unity 6000.2.12f1, URP 17.2, uGUI, Input System 1.14.2, existing Noto Japanese font.
**Spec:** `UIUX-REVISION.txt` and the approved `fpsshogi-ui-revision.html`, left menu variant.

## Global constraints
- Game name only: FPS将棋. No slogan or decorative English.
- Existing room, board and piece prefabs remain the visual material.
- 1P left / 2P right; two controllers or keyboard/mouse plus controller, either order.
- Separate join and ready presses, both ready required. Rematch retains assignments.
- King FPS defeat wins, automatic promotion, no check/checkmate. No ammo/reload mechanics added.
- HP gauge; attack/defense/skill icons and real cooldown arcs. Optional numeric HP only.
- Restore the calling page/focus. Both players confirm after a disconnection.
- Preserve prior restoration changes and dirty asset settings; do not stage unrelated work.

## Review focus
- Disconnect during a child menu: pause immediately, preserve seats, require both confirmations.
- Input held through loading/reconnect: it must not become a move, attack or second confirmation.
- Portrait cameras and objects must never affect player colliders, lighting, or FPS visibility.
- Mouse, controller and keyboard must navigate the same pages without a hidden focus trap.
- 1280x720, 1920x1080 and non-16:9 displays must keep controls visible and gauges aligned to player viewports.
