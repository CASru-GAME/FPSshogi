# モデル確認・修正記録

対象はインポート済みFBX 30点（アニメーション用を含む）と、使用中の武器・駒・投射物・和室です。元FBXの形状と表示用メッシュを比較し、実用モデル45点を6方向から撮影しました。元データを残したまま、表示用モデルと再生成処理を修正しています。

## 修正内容

| 対象 | 確認できた問題 | 対応 |
|---|---|---|
| 弓 | 弓本体と追加した弦の平面が90度ずれ、弦の先端が弓につながっていなかった。元FBXの固定弦も残っていた | 弓の向きを修正し、固定弦を除去。実際の弓の先端から動く弦の接続位置を求める |
| 弓・矢 | 弦の復帰位置が固定値で、モデルの形状と独立していた | プレハブの接続位置を基準に発射・番え直しを動かし、矢の後端を弦へ追従させる |
| 矢 | 構えている矢と飛んでいる矢でメッシュ、材質、スケールが異なった。羽根も木・革の材質になっていた | 両者を同じメッシュと材質へ統一。発射時に見えている矢の大きさを引き継ぐ。羽根を専用の淡色材質へ変更 |
| 刀 | 軽量化後の刃の縁に細かな欠け・ちらつきが見えた | 約2.1万三角形の元形状を保持し、薄い刃への一律の軽量化をやめる |
| 短銃・長銃・砲台 | 銃口位置がモデル全体の中心線に置かれ、実際の銃身より下にずれていた | 銃身先端の形状から銃口位置を決め、砲台も同じ位置を使用 |
| 武器全般 | 刀・薙刀・銃・短刀・軍配に面積のない三角形が残っていた | 面積のない面を除去し、境界・材質スロット・UVを保持 |
| 飛行中の矢 | 重力で軌道が曲がってもモデルの向きが発射時のままだった | 物理移動の向きに矢先を合わせる |

## 確認範囲

- 武器：槍、短銃、刀、赤・青の薙刀、長銃、弓、短刀、軍配、砲台。
- 駒：歩、香、桂、銀、金、角、飛、王、玉、復元した黒い角。表裏と盤上の成り表示を確認。
- 投射物：主武器・副武器の矢、鉄炮。鉄炮は完成版由来の球形モデルで、形状欠損は認められませんでした。
- 和室：盤・駒台、畳、壁、天井、柱、襖、障子、掛け軸、床の間、トロフィー、本、箪笥、座布団。軽量化段階（LOD）も比較。
- 構え、攻撃、ズーム、防御、各スキル、1P・2P、成り駒での表示と戦闘動作。

## 検証

| 検証 | 結果 |
|---|---:|
| モデルの接続・形状・材質参照 | 173 PASS / 0 FAIL |
| 全キャラのモーション・弓の発射／番え直し | 124 PASS / 0 FAIL |
| 将棋・FPS戦闘 | 199 PASS / 0 FAIL |
| 既存の表示検証 | 132 PASS / 0 FAIL |
| 和室・盤・成り駒の実画面 | 27 PASS / 0 FAIL |
| 和室UI | 113 PASS / 0 FAIL |
| 重力で曲がる矢の飛行姿勢 | 4 PASS / 0 FAIL |
| Windows版の8武器・エフェクト・実描画 | 43 PASS / 0 FAIL |

修正前の形状検査は17項目が失敗し、修正後にすべて通過しました。独立したコードレビューで重大な問題は指摘されませんでした。レビューで提案された飛行姿勢の検証も追加し、修正を外した状態では2項目が失敗、修正後は通過することを確認しました。

通常のWindowsビルドは成功（エラー0、既存の非推奨API警告1）。8種の武器を実行ファイルでも確認し、弓の発射・番え直しの画像を保存しました。非表示起動では画像が黒くなるため、最終確認は画面を表示して行い、全キャプチャの描画検査も追加しています。最終の実行検証記録は `VisualReview/Models-Verified/Native-Visible` です。

比較画像と全モデルの多方向表示：[モデル確認ギャラリー](../VisualReview/Models-Final/Gallery/index.html)。単体の画像は各モデルを画面に収めて撮影しているため、相互の大きさの比較にはゲーム内画像を参照してください。

詳細なモデル一覧は `VisualReview/Models-Final/inventory.tsv`、形状診断は `geometry.txt`、自動検査結果は `VisualReview/Models-Verified/checks.txt` にあります。診断の面数・法線警告は欠損の断定ではなく、元の薄い面や意図的な開口も含むため、画像と元形状を併せて判断しています。

## 再現手順

Unityエディターで `.utmp/model-repair/audit.txt` に任意の名前を書くと、`VisualReview/Models-<名前>` へ6方向の画像と一覧を出力します。`check.txt` は同じ場所へモデル検査結果を出します。使用中のシーンは変更しません。

武器の再生成は既存の `VisualRepairBuilder` の `weapons` コマンドを使用します。再生成処理にも修正を反映済みです。`Tools/create_model_gallery.py`（Pillow使用）で比較用HTMLを作成できます。Unityのプレビュー描画は[Unity公式のPreviewRenderUtility実装](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Editor/Mono/Inspector/PreviewRenderUtility.cs)に沿って使用しています。
